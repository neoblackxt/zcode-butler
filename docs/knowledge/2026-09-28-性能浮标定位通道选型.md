## 一、决策问题

要决定什么:输入框几何(位置/高度/主题)的**运行时获取通道**——性能浮标自适应定位的地基。

选错的代价:通道更换 = 探针 + 锚契约 + 宿主消费逻辑全链重写(约一天工作量,且需用户重新实机验收)。这个代价在本弧线内真实付出过一次:CDP 路线假锚测试全过后真机即死,全部作废换轨 UIA(见复盘 `docs/retrospectives/2026-09-28-性能浮标定位之路.md` 第 3 部分)。

## 二、问题域形态

悬浮窗在 ZCode 进程外,输入框几何(DOM rect)必须跨进程取得。可选通道按信息源分层(常量锚/像素扫描/CDP/UIA),边界在"信息保真度"与"宿主侵入性"的权衡上。

关键领域事实(本弧线实测写死):

1. **打包版 Electron 41 静默丢弃远程调试开关**:命令行带 flag、主进程零监听;显式 `--user-data-dir` 指原目录无效;开源源码(`packages/desktop/src/main/index.ts`)核实仅 `!app.isPackaged` 时 append 9229 且无 removeSwitch——是 Chromium 136+ 安全限制的继承,非应用过滤。
2. **Chromium a11y 惰性激活**:默认不生成完整 web 无障碍树,收到首个 UIA 查询(WM_GETOBJECT)后数秒内激活;contenteditable 暴露为 Edit 节点,`ClassName` 即原版 Tailwind 类字符串(如 `min-h-10 max-h-40 overflow-y-auto…`)——天然版本无关的锚点句柄。
3. **UIA 客户端连接会劣化**:长期运行的查询进程可能对活窗口返回空树(新进程立即可见);后实证为 Chromium a11y 模式**全局回落**(新旧进程同空,非进程私有;来源:复盘 §4.3),机制未明,工程对策=自愈接力。
4. **a11y 树角色随应用状态变**:回合运行中 composer 非编辑态,Edit 掉出树——降级锚须选状态恒定的节点(工具条按钮恒在)。

## 三、能力边界

| 通道 | 能 | 不能 |
|---|---|---|
| 常量锚 | 单一校准布局下零成本精确 | 感知任何布局变化(侧栏/分栏/面板/多行) |
| 像素扫描 | 一次性校准与验收采样(本弧线的实际用途) | 运行时伺服(v0.1~v0.7 已证伪:色彩/缩放/主题敏感) |
| CDP | DOM 全量信息(保真度满分) | **在打包版 ZCode 上存在**(事实 1) |
| UIA | 元素矩形+ClassName(类名=原版 Tailwind 串) | 文本语义外的 DOM 细节;连接会劣化;角色随应用状态漂移 |

## 四、选项对比

| 维度 | 常量锚(v0.11) | CDP(v0.12 原设计) | UIA(v0.12.2 定案) |
|---|---|---|---|
| 启动侵入 | 无 | **要求 ZCode 带开关重启**(用户操作) | 无 |
| 布局自适应 | ✗(单布局) | ✓ 全量 | ✓ 几何+类名(无文本) |
| 时延 | 0(纯公式) | ~33ms 可调 | ~120ms 实测稳定 |
| 通道可靠性 | — | **被 Electron 打包策略杀死** | 连接劣化(已自愈兜底) |
| 维护面 | 布局常量漂移靠手调 | node 常驻进程 | PS 探针进程+锁+接力 |

## 五、选型判断与理由链

**结论:UIA 通道 + 基线常量降级。** 理由链:

1. CDP 不可达是**宿主策略级**事实(源码核实)而非配置问题——不可达的选项无论多好都不构成选项。
2. UIA 三短板(预热期/劣化/角色漂移)都是**工程可兜底的运行期现象**,且每条兜底(等待/自愈接力/降级锚)已有实测;而常量锚的短板(单布局)是**结构性无解**——可兜底的短板优于无解的短板。
3. 保留常量锚为探针失联 >10s 的降级路径:失败时退到已知正确的东西,优于失败时消失。

反向路径(结论的边界条件,非默认计划):

- 若 ZCode 未来官方支持调试开关(或内置扩展 API 暴露输入框几何),CDP/官方通道应重新评估——UIA 是当前约束下的最优,不是终局。
- 若 a11y 树在关键路径持续不稳,备选:AutomationFocusChanged 事件驱动替代轮询;或回到「常量锚 + 布局枚举」(侧栏开/合/分栏各一组常量,WinEvent 探测切换)。

## 六、显式预测(供复盘对质)

| # | 预测 | 依据 | 验证时点 |
|---|---|---|---|
| P1 | ZCode 版本更新(3.14.x→后续)后,Tailwind 类名字符串 `min-h-10 max-h-40…` 大概率保持——Tailwind 类是原子化的,重构组件时类组合易变但**编辑区容器的这几条约束类**(min-h/max-h/overflow/leading)语义稳定 | 官方开源仓库 styles.css 注释「显式补 @source 让 Tailwind 始终扫描 UI 包源码」,类名是布局契约 | 每次跟随 ZCode 升级后跑一次性 UIA 探测;失效则改锚 `aria`/结构启发式 |
| P2 | UIA 查询对 ZCode 渲染进程的性能影响可忽略(120ms 轮询一读) | Chromium a11y 激活后增量维护树,单属性读为 O(路径) | v0.13 接真数据后对比 ZCode 内存/CPU 基线 |
| P3 | 探针自愈接力在长期运行中自稳定(独占句柄锁后不再出现双写者) | 锁语义由 OS 保证,进程死亡即释放 | 用户日常使用一周内观察锚文件是否再出现 0 字节/陈旧 |
| P4 | 回合运行中"工具条最右 Button"降级锚在 ZCode 改版(工具条增删按钮)时仍成立——因为取的是**空间上最右**而非特定按钮 | 工具条右端永远有动作按钮(发送/加入队列) | 同 P1 触发点 |

## 七、坑预告与待实测项

- ⚠️ UIA 劣化机制未明(仅工程兜底,Chromium a11y 全局回落的触发条件待挖)——复盘 §八 已挂
- ⚠️ a11y 预热期数秒(启动后浮标隐藏窗口)
- ⚠️ 聊天页签名依赖「切换模式」按钮**中文 NameProperty**——切英文 UI 即失效(复盘对质 P4 时发现,决策时未预见)
- ⚠️ 附件行 Image 带状扫描的误判边界(会话末条消息含图且紧邻输入框时可能偏高)——v0.12.4 引入,待真实附件复验
- ⚠️ P2(性能影响)未做正式基线对比,当前只有"用户未报卡顿"的间接证据
