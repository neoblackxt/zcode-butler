## "C:\Users\27844\Desktop\zcode-butler\AGENTS.md" , 我正常说的三端应该是: zcode缓存,github,桌面源码 , 但是AGENTS.md的三端是什么意思

这份 AGENTS.md 里其实没有“三端”这个词——它写的是「**三份副本**:仓库(正本)↔ 镜像 ↔ 缓存」([AGENTS.md:40](C:/Users/27844/Desktop/zcode-butler/AGENTS.md))。和你的口径差在第三份：**它数的是镜像，你数的是 GitHub**。

两套口径其实是两个视角：

|      | 你的「三端」                 | AGENTS.md 的「三份副本」                       |
| ---- | ---------------------------- | ---------------------------------------------- |
| 视角 | 交付一致性：哪些地方必须一致 | 本机分发链：插件从改完到跑起来经过哪些物理副本 |
| 三份 | 桌面源码、GitHub、ZCode 缓存 | 仓库(桌面)、镜像、缓存                         |

AGENTS.md 是从「插件生命周期」那一节的需要出发的：改完仓库后，到插件真正在 ZCode 里跑起来，本机磁盘上有三份会各自存在的文件——**仓库 →(marketplace 刷新，每日约 02:30)→ 镜像(`~/.zcode/cli/plugins/marketplaces/zcode-plugins-personal/`)→(UI 点更新)→ 缓存(`.../cache/.../0.2.1/`)**,而且「安装/更新的拷贝源是镜像不是本仓库」。这三份都可能静默漂移，所以要写同步纪律：改仓库后手动同步缓存(代码立即生效)、手动同步镜像(更新按钮立即生效，不刷就等每日自动)。

GitHub 在这份文档里不算一份独立副本，理由有两个：一、它和桌面仓库是同一个 git 内容，push/pull 就保证一致，不需要生命周期纪律来管；二、**镜像本身就是一个 git clone,origin 就指向 GitHub**——「同步镜像」的实际操作就是 `git fetch origin && git reset --hard origin/main`,你的三端里的 GitHub 兼任了镜像同步的传输层。今天这轮我就是这么做的：push 三个提交到 GitHub,再把镜像硬重置到 origin/main。

所以两边不矛盾，合并起来物理上是四份：桌面仓库、GitHub、镜像、缓存——桌面↔GitHub 由 git 管，镜像↔GitHub 由 ZCode 自动刷新(或手动 reset)管，你日常要盯的就是你说的三端。这个澄清之前在开发日志 2026-09-30(二轮)条目里也记过一句(「用户澄清其三端=桌面源码↔ZCode插件缓存↔GitHub,镜像非其所辖」)。
