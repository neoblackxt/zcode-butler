## 一、决策问题

要决定什么:性能浮标"实时速度"(≤1s 更新,**覆盖思考+文字**)的外部数据源通道。
选错的代价:轻则数字死寂(用户已三次以体感实测否决);重则侵入宿主导致 ZCode 无法启动(方案 B 已实证此代价,2026-09-29 事故)。

## 二、问题域形态

ZCode(3.14.x)的事件流架构(全部本机实证,来源见复盘):
- 流式增量(text_delta/reasoning_delta)只存在于**内存 event store → 桌面私有 stdio 管道**,任何磁盘文件流式期间零写入;
- 磁盘族(rollout JSONL / db.sqlite part 表 / app log)全部**完成级落库**;db 的 WAL 高水位复用使"文件尺寸冻结"成为观测假象(内容在写,但行不流式增长);
- UI 投影层:可见文字逐帧渲染(216ms/批);**思考块折叠渲染,流式期间不在 DOM**,完成时大块到达;
- hook 契约 7 事件无流式;官方无对外事件出口(feedback #525/#547/#761 零回应;对照:OpenCode 有进程内总线+官方 /event SSE,Codex 有官方 app-server RPC);
- 启动链有官方留的注入点(ZCODE_AGENT_SERVER_COMMAND),但 3.14.4 起自定义命令需满足硬性存储准备。

**形态学结论**:外部进程的观测面只有四个——磁盘(完成级)、UIA(渲染投影,文字段)、网络层(可代理,SSE 含思考)、启动链(可注入,已被 3.14.4 封死一档)。实时含思考 = 只剩网络层或等官方。

## 三、能力边界

| 通道 | 能 | 不能 |
|---|---|---|
| 磁盘族(db model_usage/part/rollout) | 真值(平均/TTFT/校准)落库即得,精确 | 流式增量(行不增长);思考实时 |
| UIA 投影层(转录区 TextPattern) | 文字段实时(216ms/批);当前会话天然绑定 | 思考(折叠不可见);长驻客户端 TextPattern 路径静默劣化(~15min,几何锚仍活) |
| stdio wrapper(ZCODE_AGENT_SERVER_COMMAND) | 字节级全量含思考,帧 30-70ms | **在 3.14.4 桌面存活**(启动死锁);版本漂移风险极高 |
| 本地反向代理(改 baseURL) | SSE 逐帧含思考(30-70ms);应用层逐字节保真;可一键回滚 | 免侵入(动 ~/.zcode/v2/config.json 红线文件);代理挂=消息发不出(但 ZCode 本体可开) |
| 官方接口 | (若提供)一切 | **当下不存在**;诉求已挂 feedback 三 issue 零回应 |

## 五、选型判断与理由链

**现状定案(已执行)**:v0.13d = A(磁盘真值 + UIA 文字实时)为回退底座——零侵入、真值精确,其"思考不实时"是当前物理上限的诚实表达。
**悬置决策**:完整实时选 **C(本地反代)** 为唯一活路——B 已被 3.14.4 事实封死(恢复即再坏);D 无时间表;C 的失败模式(请求链、可回滚)远优于 B(启动链),且只依赖智谱公开 SSE 格式。识别安全:智谱按 `x-zcode-*` 请求头全家桶+key 识别(明牌),应用层逐字节转发不受影响;TLS 指纹差异被逻辑排除(第三方 agent 口音各异均无折扣→判据必在请求头),curl-impersonate 为兜底备手。
**执行门槛(事故后立规)**:C 动手前必须①离线合成流测试②config diff 用户过目③改后三验证(消息可发/思考段出数/额度速率符合 1.5x 口径)。
