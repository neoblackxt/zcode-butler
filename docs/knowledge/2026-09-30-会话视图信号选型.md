# 会话视图信号选型(性能浮标「当前会话」归属通道)知识地图

> 决策前认知文档:回答"知道什么、选项怎么比、预判如何"。
> 决策后冻结,复盘时对质。存放:docs/knowledge/YYYY-MM-DD-主题.md。
> 补记说明:本弧为灭火节奏,决策与实施同日完成(v0.13f,2026-09-30),地图为实施后当晚补写;认知内容为决策时点的真实状态,已验证事实标注来源,未验证判断一律入预测节。

## 一、决策问题

要决定什么:性能浮标「分会话显示」的归属依据——**「用户当前正在查看哪个会话」的运行时信号通道**。数据侧(db `model_usage` 按 session_id 全量)已就绪,缺的是"当前看的是谁"。

选错的代价:错归属 = 直接显示错误会话的数据(语义错误,非体验问题);通道更换 = 探针扫描 + 文件契约 + metrics 解析全链重写。用户实际付出过一次:v0.13e 只押 app log `session.resumed`,切回已驻留会话即失灵(见开发日志 2026-09-30 三轮)。

## 二、问题域形态

ZCode 多会话并行,「驻留」(resident)是关键概念:近期用过的会话保持热态,切回**不重新加载**。信号通道必须覆盖"驻留切换"这条路径。本弧实测写死的领域事实:

1. **app log 的 `session.resumed` 只在非驻留打开/恢复时发**;切回已驻留会话时 log 完全静默(实测:切走有 resumed、切回六分钟窗口零会话事件、仅内存采样,直到发首条消息才有 `turn.started`)。
2. 主窗口标题恒为「ZCode」,不含任何会话信息(实测 GetWindowText)。
3. db 的 `input_history`/`session_input` 只记**已发送**输入;`session.time_updated` 只随活动 bump,纯查看不写——db 无视图痕迹。
4. UIA 树:侧栏会话条目为 Button,**当前条目 ClassName 含 `bg-selected`**(非当前为 `hover:bg-surface-hover`),`Name` =「标题 相对时间」(刚刚/4小时/2天…);SelectionItemPattern 不可用,选中态只体现在样式类。
5. `session.title` 可变(改名/title_source 生成),侧栏条目名与 db title 同源、改名即同步。

## 三、能力边界

| 通道 | 能 | 不能 |
|---|---|---|
| app log `session.resumed` | 非驻留打开即时、语义明确、零成本(已有 tail) | **驻留切换完全盲区**(事实 1) |
| 窗口标题 | 一次 API 调用 | 无会话信息(事实 2) |
| db 各表 | 历史聚合全量(数据侧) | 只反映活动,不反映查看(事实 3) |
| UIA 侧栏选中态 | **唯一能看见「所看」的信号**(事实 4) | 侧栏收起/当前行不可见时无信号;依赖 Tailwind 类名串;需剥时间后缀再映射 title |

## 四、选项对比

| 维度 | v0.13e(仅 log 三信号) | v0.13f 定案(log 三信号 + UIA 视图通道为主) |
|---|---|---|
| 驻留切回 | ✗ 停在上一个会话,等首条消息 | ✓ ~2s 跟随 |
| 侵入性 | 无 | 探针 +~2s 一次 Button 扫描 + 一个文件契约(view.json) |
| 误切风险 | 无 | 查不到不切(安全退化)/同名按 time_updated 最新 |
| 新增依赖 | — | `bg-selected` 类名 + `session.title` 契约 |

## 五、选型判断与理由链

**结论:三信号分层——(a) UIA 视图通道为主,(b) `session.resumed` 次之(非驻留),(c) 其余会话首请求跟随兜底;三信号汇入同一「切换 + 按 db 历史重建」。** 理由链:

1. 驻留静默是平台行为而非缺陷,log 通道**结构性**够不着——在 v0.13e 框架内怎么调都修不了切回,必须引入看得见 UI 状态的通道。
2. UIA 通道可行性已被定位弧(`2026-09-28-性能浮标定位通道选型.md`)整体验证(同树、同探针、劣化自愈机制现成),增量只是一个扫描与一个文件;`bg-selected` 是选中态语义在 Tailwind 体系里的自然落点。
3. 标题映射的固有歧义(同名会话/改名竞态/剥尾启发式切坏标题)全部收口为「查不到不切」:最坏结果是显示滞后(30s 心跳重试),永远不会错误归属——宁可旧、不可错。

反向路径(结论的边界条件,非默认计划):

- 若 ZCode 未来在 app log 暴露视图切换事件(如 `session.viewed`),或在扩展 API 暴露当前会话 id,应弃 UIA 扫描改用官方信号——UIA 是当前约束下的最优,不是终局(与定位通道结论同构)。
- 若 `bg-selected` 失效高频化,备选:条目 AutomationId/相邻分组时间戳做映射键;或退回「log 三信号 + 切回后首请求快速跟随」并在 UI 上明示归属会话标题。

## 六、显式预测(供复盘对质)

| # | 预测 | 依据 | 验证时点 |
|---|---|---|---|
| P1 | ZCode 前端样式重构时 `bg-selected` 拼写可能变;失效表象 = view.json 停更、归属停在最后一次成功映射(resumed/首请求路径不受影响,整体降级不坏) | Tailwind 原子类是状态契约但拼写随样式系统 | 每次 ZCode 升级后看 view.json 是否持续更新 |
| P2 | 侧栏收起使用的用户会遇到「切回不跟、重新展开 ≤2s 恢复」——通道静默退化可接受 | 扫描对象不存在即无信号 | 用户日常反馈 |
| P3 | 改名竞态(侧栏先渲染/db 落库滞后)在 30s 心跳内自愈;db 延迟 >30s(未见过)才卡到下次名字变化 | 心跳重试已实测(回放:未知名不切/心跳重试/切回恢复) | 用户改名实测 |
| P4 | 同名会话在真实使用中罕见(标题=首输入,自然语言重复率低);高频出现才需升级映射键 | db title 样本观察 | 日常使用;出现即记日志 |

## 七、坑预告与待实测项

- ⚠️ `bg-selected` 是样式实现细节而非语义契约——本通道最脆的一环(已列 P1);换血时的兜底是三信号分层,不是单点
- ⚠️ 侧栏非会话行(分组/新建任务)若也带 `bg-selected` 会误读——`task-row` 过滤 + 查库不到不切双保险,实测未现
- ⚠️ 剥尾启发式(≤6 字符尾 token)可能切坏以短词结尾的真标题——落入查不到不切,不误切;英文带空格标题尤甚
- ⚠️ 归属恢复上限 = 探针心跳周期(30s)——不是切换延迟上限(切换 ~2s),两者别混
