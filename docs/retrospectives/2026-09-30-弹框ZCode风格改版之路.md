## 一、弧线摘要

六个版本、一天之内:弹框从「设计稿占位文案」走到「ZCode 官方设计语言的忠实移植 + 全口径数据」。中间经历两类故障——**口径故障**(周窗口锚错、模型明细整天化、合计口径错)与**审美故障**(zcode-usage 内容复刻被否、头部方案四连返工)——最终以「ZCode 开源仓库的设计令牌逐值提取」收束。

## 二、做对了什么(可复用的方法)

1. **开源仓库即设计真相源**。用户指向「ZCode 设置-使用统计两页」后,没有凭截图猜样式,而是定位 [zai-org/ZCode](https://github.com/zai-org/ZCode) 仓库,把两页面组件源码(AboutUsage/CodingPlanUsagePanel 等 26 文件)拉到桌面,从 styles.css 逐值提取 zai-dark 主题令牌(卡面 5% 白/边框 10% 白/图表色板/字号阶梯)。**设计争议的终审不是审美讨论,是源头文件**。
2. **五组同屏预览选型**。iframe 各带 `?v=1..5` 参数装一个对比页放桌面,用户同屏比选后点 V1——把「来回描述偏好」变成「指着选」,一次收敛。
3. **程序化拆图代替视觉**。本模型无视觉,用户参考图全靠 Windows OCR(逐词坐标)+ 像素采样拆解:bigmodel 控制台额度卡排布(标签+ⓘ/大字%已使用/细条/重置时间)与头部两行结构都是从像素反推的。无视觉 ≠ 不能做 UI。
4. **自适应高度用实测不用估算**。fitPopHeight 每次渲染后量内容真实高度折算舞台 px,path 随高重描——各弹框 437–647 自动收缩,底缝稳定 ~6 舞台px。

## 三、翻过什么车(根因,按贡献排序)

1. **接口行为自洽被当成口径正确**(v0.6.0 周窗口):「接口按我给的起点返回数据」只证明执行忠实;十三轮的"实测对齐"验证缺了**用户真值校准**这一环,十四轮 7.50 亿真值一击证伪。教训已入知识地图《7d周窗口口径定标》。
2. **照抄 UI 时越权动容器**:用户说「改成 zcode-usage 的 UI」,第一版把配色体系、气泡底色、头部全换了——挨骂「阴间配色,只让你动内容没让你动弹框」。**授权范围以用户原话为界:让动什么才动什么**。
3. **截图语义误判**:用户发来一张图说「类似这样」,实为**现状示丑**(截我自己的 UI 骂丑),我却当设计稿逐像素抄了。返工两轮才到「zcode-usage 同款单行 meta」。**收到截图先确认是设计稿还是现状**。
4. **头部挤折行**:BigModel 标+长标题+徽标+刷新钮自然宽 686 > 气泡内容区 618(690−2×36 内边距),flex 把标题压成两行——用户一眼看出「第一行跑了」。修:元素自然宽必须 scrollWidth 实测,**禁估算**;标题 nowrap+不可压缩,5h 态刷新钮收成图标。
5. **配色信息先后传错两次**:先「5h/7d 恒绿」,用户更正「说错了,5h 恒蓝 7d 恒绿」——两轮才到位。**多目标配色一次复述确认再动手**,成本低于返工一轮。
