## 三、分章叙事(时间为经、主题为纬)

### 第 1 部分 语义重构时代(09-28 深夜~09-29 凌晨)

#### 1.1 补丁堆的自我了断 [日志 09-29(凌晨)条]
v0.12.5 b-e 四轮补丁(冻结三防线/欢迎页邻接/重显 MoveTo/确认期门)后,用户裁决弃补丁:f/g 重构为"消失/出现"二态制(探针只报真值+身份判定,宿主状态机裁决一切显隐)。关键实证:探针侧节流门在宿主状态机存在后全是纯延迟("消失太慢"的 ~600ms 根因);滑翔删除后 h 轮试图以"试探跟随"复活,用户实测"太突脸"否决——**大位移跟随动画在此场景必扑脸,二态制为终态**。
#### 1.2 两次事故性 bug 均为"状态不成对写" [同上]
现身忘同步滑翔目标→窗口被拉向陈旧坐标→3Hz 闪烁循环;渐变检测器来不及武装(动画首帧即 >100px)→换试探策略。工程教训:cur/tg 类成对状态必须原子更新。

### 第 2 部分 真数据三迭代(09-29 02:00-03:50)

#### 2.1 rollout 版与"完全按照"的代价 [日志 09-29(下午)条]
metrics.mjs 采集器(tail rollout+app log)端到端跑通(statsAck 回执),但流式期间零数据(rollout 完成级落盘)。用户质询"看源码了吗"——此前仅读 WebFetch 摘要(含 paraphrase)即声称"完全按照 oc-tps";补读 tui.tsx 全文后修正两处格式偏差。**教训:声称"完全按照 X"前必须逐字读 X,模型摘要不算。**
#### 2.2 调研工作流与两悬案破解 [工作流 artifact]
8 研究员(GLM-5.3-FlashX,4 stepfun 检索/4 GLM 检索)+盲审:破解锯齿悬案(2887↔3118=侧栏两布局时代真右缘,±115px=231/2);修正 UIA 劣化认知(每客户端连接私有,非常驻进程固有);发现生态先例 zcode-meter 与 db part 表通道。
#### 2.3 db 认知三连跳(本弧最富戏剧性) [part-trans 实测]
凌晨:"db 流式期间字节冻结"(文件尺寸观测)→工作流:"冻结是 WAL 高水位假象,行在写,part 表可流式"(rank1)→实施后实测:"行确实落库但**流式期间不增长**"(150ms 行级观测 70s,31 秒思考+写作零增长,完成时以最终长度一次性落库)。**两次反转的共同根源:观测手段错(尺寸≠内容;新行存在≠行增长)。**
#### 2.4 UIA 投影层终态(v0.13d)
anchor 探针每 240ms 读转录区 Document 文本长度(每 tick 重取,缓存引用返回旧快照):文字段 216ms/批真实时;思考在 DOM 折叠不可见(bigjump +14090 完成时到达);长驻探针 TextPattern 路径 ~15min 静默劣化(几何锚仍活)→5 分钟自愈接力;积压跳变过滤(gap>3s 或 >600 字符/s 只重置基线)。

### 第 3 部分 方案 B 的生与死(09-29 17:50-18:20)

### ✗ 项成因分析(认知边界)

1. **文件尺寸≠内容写入**(WAL 假象)与**行存在≠行增长**:两次反转证明"仪器选择"先于"结论 trust"——growth-watch 采样 size、调研员探针看新行,都没直接测"同一行的增长曲线"。行级 SQL 快照 diff 才是终判。
2. **宿主级注入的冒烟覆盖律**:验证"子进程能被拉起"≠验证"宿主启动链完整通过"——B 事故的死点恰在 wrapper 之外的桌面逻辑。
3. **体感即验收**:数字更新的"理论节拍"与用户看到的"变化间隔"是两个量——显示链路上任何一环死寂(思考不可见)都会让理论值失去意义。
4. **版本漂移**:源码结论自带版本保质期(3.14.3→3.14.4 一天),动启动链前核对目标机版本是硬前置。

## 五、决策复盘(否决/换轨的模式归类)

本弧十余次反复归四类:
1. **补丁→语义**(用户两次裁决):b-e 四轮补丁的本质是给"跟随式定位"打补丁;f/g 换成"消失/出现"二态后,补丁清单大半直接作废。模式:**机制与需求语义冲突时,补丁收敛慢于换语义**。
2. **跟随动画的两次死亡**(滑翔/试探跳):视觉上"平滑"的方案在"胶囊横穿输入区"场景都成"扑脸"。模式:**小 UI 元素的大位移,隐藏-重现的心理成本低于移动动画**。
3. **观测驱动的三连跳**(db 通道):每步都有"证据",但仪器错则结论错;最终由直接测量(行增长曲线)终审。模式:**结论可信度=仪器可信度,链式二手结论会放大失真**。
4. **侵入方案分级事故**:B(启动链注入)炸在最深处(打不开);C(请求链)炸在浅处(发不出、可回滚)。模式:**侵入层级决定事故半径;宿主启动链是最高危面**。

## 六、方法论沉淀(可复用打法)

- **行级 SQL 观测器**:对"表是否流式写"的终判=150ms 周期 SELECT rowid+len 快照 diff,画增长曲线;文件尺寸/mtime/新行计数都会误导。
- **同数据新旧公式回放**:改统计口径时,用同批 DB 行按新旧公式各算一遍对比(44-50→69.8),比"感觉对"强一个量级。
- **合成帧单元测试 + 真实冒烟分层**:协议解析先喂合成帧验证保真(128/128),再真机冒烟;但**宿主级注入的冒烟必须覆盖宿主完整启动路径**(本弧血的教训)。
- **8 人调研工作流**(4+4 检索后端分组+盲审一轮):适合"通道是否存在"型排查;产出须过"直接测量终审"(rank1 被 part-trans 证伪即例)。
- **心跳让位双通道**:两数据源并存时,活源写心跳文件,备源见心跳新鲜即退避——免双计,切换零配置。
- **体感计数验收**:显示类指标,用 200ms 可见性轮询/变化间隔计数验收,不以"数据在流"代替"用户看到变化"。
