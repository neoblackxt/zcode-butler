### 3.1 技术文档诞生(2026-09-12 19:13:09)

《ZCode 插件悬浮窗 UI 技术文档:从 HTML 到原生桌面.md》由 zcode 在一次技术讨论中**一气呵成、单次成文定型**(文件创建时间 2026-09-12 19:13:09,现名 `docs/knowledge/2026-09-12-悬浮窗UI技术选型.md`——史料附件,勿删:本文 3.3 对照表的预测侧证据、macOS 二期预习材料、三平台环数学完整代码均在其内)。它把此前所有讨论收束成知识地图,直接决定了后续路线:Path B(WebView2 直载 HTML)。

### 3.2 技术文档核心内容(知识地图摘要)

1. **插件形态学**:悬浮窗是 hooks 拉起的独立进程,非插件系统内置 UI 层——选型完全自由;
2. **Figma 边界**:当图纸用(量尺寸/色值),别指望生成 WPF/AppKit 代码;
3. **Web vs 原生**:Web 把"画图形"和"管窗口"都做成声明式一等公民;本 UI 恰好落在 Web 最擅长、原生最费劲的交叉点;
4. **环数学**:SVG `dasharray = C×pct, C×(1−pct)`(C=2πr);WPF `StrokeDashArray` 单位是线宽倍数须换算;AppKit `strokeEnd` 吃 0-1 反而简单;
5. **三路径**:A 原生(85-90%) / B WebView2+WKWebView(推荐) / C Tauri·Electron;B 优于 C(与现有 Hook/Node/PS 体系贴合,免 Rust 链);
6. **壳职责表**:绘图代码淘汰,窗口/系统代码保留且加强(总量只减 30-40%);
7. **坑预告**:WebView 默认背景不透明须设 `DefaultBackgroundColor=Transparent`;字体缺失须打包;macOS backdrop-filter 层级待实测。

### 3.3 预测与实测对照表(后见之明,本文最有含金量的一节)

| Windows(WebView2) 还原度 ≈98% | 结构/布局/环/动画确实 1:1,但**透明体系全军覆没**(白底/白环/白闪/硬边四连),直到合成宿主才真正达成 | 半对:内容 1:1,合成 0 分 |

### 4.2 `$args` 自动变量事故

现象:日志只剩 `wv2 init FAILED:` 空消息。根因:事件处理器 `param($sender, $args)` —— `$args` 是 PowerShell 自动变量,**param 绑不上**,`IsSuccess` 恒空 → 误判"初始化失败" → 弹隐藏模态 MessageBox 永久阻塞 + 占死互斥量。最小复现(同属性透明窗)INIT OK 才剥离。修法:改名 `$e`。
**教训**(已入 AGENTS.md):函数/事件参数禁用自动变量名;`$args` 变体比 `$PID` 更阴——不报错、走向反转。

### 4.3 白色矩形战役:像素考古学方法论

现象:面板周围一圈 2px 纯白(255,255,255)。工具链成型:
- **GetPixel 逐列剖面**:左缘 = 背景(22,22,22)→ x5,x6 纯白(255)→ x7 过渡灰(52)→ x8 面板黑(3);
- **换色实验**:DefaultBackgroundColor 换红 → 白条不变(排除 WebView 底色);
- **负 Margin 实验**:子 hwnd 外铺 4px → 白条反而加宽到 7px(排除静态缝隙,锁定"区域与渲染相对错位");
- **强制态二分**:强制气泡常显+区域常开,一次性分离静态/动态因素。
**教训**:视觉模型对小图会幻觉(把文字 glyph 读成图标、"铃铛 3条"凭空出现)——只采信结构化结论(形态/计数/坐标);同色图形的可见性验证必须换色,不能靠阈值数像素(黑弧贴黑胶囊曾误判"弧线丢失")。

### 4.4 根因一:分层窗口 × HwndHost(v0.2.0 白底)

`AllowsTransparency=true` 只对 WPF 自绘像素生效;WebView2 是 HwndHost 子窗口,不参与分层合成 → 页面透明像素以不透明呈现(白)。且窗口化控件在分层窗口里**连初始化都无法完成**(Canvas/Grid/直接三布局证伪,WPF 自身半透明红正常渲染)。色键路线(WS_EX_LAYERED + LWA_COLORKEY)亦死:`SetWindowLong(GWL_EXSTYLE)` 在本机(Win11 26200)WPF 窗口上**假成功**(返回旧值但样式不落盘,裸窗口复测成立)。

### 4.5 rgn 时代:形状裁剪(v0.2.1,commit e10d019)

`SetWindowRgn` 把窗口裁成"面板轮廓 ∪ fab 圆"——区域外 OS 不渲染、点击穿透,白底消失。轮廓点运行时从 HTML `outline` 数组正则提取(单一正本);尺寸 780→600 DIP(用户要求改小)。连环坑:Add-Type 裸 `-TypeDefinition` 不带 using(编译失败被 SilentlyContinue 吞,$null.Count 巧合为 0);非贪婪 `\]` 在嵌套数组第一对截断(须锚 `];`);**UDF 跨进程单例锁**——复现实例与主悬浮窗共用 `~/.zcode/butler-widget-wv2` 报 `0x8007139F(ERROR_INVALID_STATE)`,复现须独立目录(这也解释了部分"时灵时不灵"的初始化失败)。

### 4.6 动态窗口区域(v0.2.2,commit 882a9ea)

fab 静态整圆+黑底 = "大黑圆垫"(用户:"大背景没办法透明吗")。改动态 rgn:默认只裁弧线细带+端帽(几何由页面 `getPointAtLength` 实测上报),悬停时 enter/leave 桥切换整圆,移开 450ms 收回。验证:脚本化悬停拍到绽开齿轮气泡;日志 rgn(open)/rgn(base) 交替与用户真实鼠标吻合。

### 4.7 根因二:推算偏差(v0.2.3,commit b086fbc)

窗口 DPI=171(GetDpiForWindow,64 DIP→114px)而页面 devicePixelRatio=1.75(600 DIP→1050px)——**两方向有效缩放不一致**,宿主推算区域比页面真实渲染大 ~3px,露出 WebView 控件区白底(248,248,248,与 DefaultBackgroundColor 无关的一层)。修法:页面 `shape` 消息上报**实测视口坐标**(getBoundingClientRect 映射 + dpr),宿主只做 ×dpr。
**教训**:DPI-unaware 探针的窗口读数被虚拟化(÷1.75)——64×600 的"错尺寸"读数其实是探针问题;窗口几何验证必须与目标同 DPI 感知级别。

### 4.8 根因三:无 alpha 摊白与动画期缺陷(v0.2.4,commit 576f424)

查证([WebView2Feedback #915](https://github.com/MicrosoftEdge/WebView2Feedback/issues/915) "opacity is not supported yet";[官方文档](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2controller.defaultbackgroundcolor) alpha 只能 0/255):窗口化无逐像素 alpha,页面所有透明/半透明像素摊到白底。三连修:
1. body 涂面板黑(读 `--panel` 变量,主题换色联动)——边缘抗锯齿与气泡环不再泛白;
2. **file:// 被 WebView2 磁盘缓存**(改版跑旧页的假象)→ 每次复制随机临时路径加载;期间尝试 `?v=` 查询串被 `[Uri]` 编码成 `%3F` 坏路径、pre-Show 裸 `EnsureCoreWebView2Async` 挂起,均弃;
3. CSS transition **动画期合成层渲染为白**(气泡绽开白闪;浏览器同代码正常、静态强制态全黑——二分定位为动画期缺陷)→ 宿主模式禁过渡,弧线↔气泡瞬时切换。

### 4.9 天花板(v0.2.5,commit e1339ca)

胶囊轮廓沿渲染路径每 4 舞台px 重采样(~810 点,rgn 紧贴曲线)。但 1px 硬边台阶是 **rgn 二值边缘的本质属性**:ZCode 白主题下曲线段"毛毛糙糙"(用户实测反馈);且黑底近似与具体颜色耦合,用户规划"悬浮窗会换色、ZCode 背景会变"——该方案不可持续。Acrylic 路线否决(DefaultBackgroundColor 无效 + 硬边依旧)。结论:任意背景平滑边缘只有逐像素 alpha 一条路。

### 5.5 上屏三件套与三个死锁

三件套(缺一件的症状):
1. `CreateTargetForHwnd(hwnd, topmost=TRUE)`——FALSE 时页面连 rAF 都不跑,shape 消息不到,纯透明;

3. `IsVisible=true + NotifyParentWindowPositionChanged()`——收尾保险。

1. 裸 `.Result` 不泵消息:控制器创建会向宿主窗口 SendMessage → 死锁。修法:`PumpWait`(PeekMessage/Translate/Dispatch 循环 + Sleep(15));
