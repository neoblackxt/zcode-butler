## 一、背景与结局

从"输入框下方空带里一行小字"出发,用户要求升级为"贴输入框右上方、适配一切布局状态、与官方 UI 同风格"的性能浮标。一天之内经历四个时代:源码考古设计(八方案定稿 B+E1)→ 常量锚时代(四布局证伪,一次)→ CDP 时代(假锚测试全过、真机即死,Electron 打包策略证伪)→ UIA 时代(通道成立,但被探针生命周期、UIA 劣化、a11y 角色漂移连攻三轮,终以独占句柄锁+降级锚链+盲窗保持收官)。结局:插件 0.2.4,定位/出现时机/主题/滑翔四维自适应,三端同步,假数据待 v0.13 接 rollout。

## 三、分章叙事(时间为经、主题为纬)

### 第 1 部分 设计时代(09-28 上午 | sess_420c274e | 700eca4)

#### 1.1 源码考古替代目测 [09-28 | 日志「八方案原型与 B+E1 定稿」条 | 700eca4]
不从截图猜样式,直接读 zai-org/ZCode 开源仓库:ChatPromptEditor.tsx 的壳类名、LexicalChatInput.tsx 的编辑区规格、styles.css 的 theme-zai-light/dark 全量 token。本地 asar 因哈希 chunk/testid 打散被否。产出自包含原型页,八方案对照,用户四轮拍板定稿 B+E1(双胶囊+火花线+呼吸绿点)。

#### 1.2 原型验收方法的三次升级 [同锚点]

### 第 2 部分 常量锚时代(09-28 上午-午 | 同会话 | 700eca4)

#### 2.1 WebView2 光栅化第一课 [日志 v0.11 条]
HTML 按物理像素写,实机只见孤字"0.76s"——CompositionController 按 dpr 1.75 光栅化,视口=物理÷1.75,物理值被再放大裁切。回到"页面写 CSS px、窗口给物理"的老实践。

#### 2.2 校准与一次弦高验证 [同锚点]
像素分类扫描实测 composer 右缘 2824(假设值差 281px!)、上沿 1859、高 182;右缘对齐用圆角弦高公式(6.3px)证明"采样行差 6px=圆角内收,中心处精确齐平"。

#### 2.3 被证伪 [用户四布局截图 | 日志 v0.11 条]
仅校准态布局正确;折叠偏 63(=偏移常量本身)、无面板偏 294、分栏完全脱锚。**常量对一种布局精确,对布局集合是错误抽象**。原 anchor-plan 的核心洞察"流式期输入框恒为空=常量成立"技术上没错,错在用户观看浮标的场景远不止流式期(打字中/切页/看历史都是)。

### 第 3 部分 CDP 时代(09-28 午 | 同会话 | 700eca4)

#### 3.1 假锚测试的虚假安全感 [日志 v0.12 条+ADR 条]
node 探锚+锚文件契约,假锚注入 5 态测试全过(逐像素)。测试暴露的真 bug(锚文件删除不触发重估→冻结)也修了。**但整个测试链没覆盖"通道本身不可达"这一层**——测的是"有锚时消费端对不对",没测"锚的生产端在真机上存不存在"。

#### 3.2 真机侦探链 [日志 ADR 条]
命令行带 flag ✓→netstat 零监听 ✗→假设 Chromium 136+ 默认目录限制→补 --user-data-dir 指原目录→仍零监听(假设半证伪)→asar 扫描(命中全是内置 Playwright)→开源源码定案:仅开发态 append 9229。**打包版 Electron 上 CDP 是设计性死路**。启动器与 mjs 探针当轮删除,不留尸体。

### 第 4 部分 UIA 时代(09-28 午-深夜 | 同会话+fork | 700eca4..147a663)

#### 4.1 通道验证 [日志 ADR 条]
一次性 UIA 探测:composer 以 Edit 节点暴露,ClassName=原版 Tailwind 类字符串,坐标与像素扫描交叉一致。零启动开关。实施要点:取最底部匹配(行内编辑同款类名)、物理坐标契约免换算。

#### 4.2 探针生命周期四代演进 [日志「探针三连修」条]
①无锁(三探针并发,tmp+rename 互删锚文件)→②pid 文件锁+单写者直写(仍有"存活检查→退出"竞态;自愈接力第一版接力棒落地)→③先放锁再拉继任(修接力)→④**独占句柄锁**(FileShare.None,进程死 OS 自动释放)+ZCode 亡 10s 自退。每代都由真实故障推动,没有一代是预防性设计。

#### 4.3 UIA 劣化与 a11y 角色漂移 [日志「探针三连修」+v0.12.4 条]
两个运行期现象:老探针对活窗口返回空树(新进程可见)——实证为 **Chromium a11y 模式全局回落**(新旧进程同空,非进程私有问题),对策自愈接力+盲窗保持;回合运行中 Edit 掉出树(composer 非编辑态),对策降级锚=工具条最右 Button(数学同源:右缘+21/高恒 182)。

#### 4.4 状态语义的三次细分 [日志抖动条+v0.12.4 条]
健康的 none(输入框不在:设置页)≠ 失联(通道断)≠ 劣化窗口(n:0,树回落但 composer 在)——三态三种行为(隐藏/保持→基线/保持原位);窗口移动(WinEvent 帧级)≠ 布局变化(tick 滑翔)——统一偏移源+滑翔期烘焙当前位;终值目标 ≠ 当前位置——烘焙错对象就是抖动本身。

#### 4.5 v0.12.4 三验收 [fork 会话 | dde4db3]

### ✗ 项成因分析(认知边界)

- **常量锚洞察的错位**:逻辑推理本身无懈可击(流式期→空输入框→固定高度),错在**把"浮标有信息价值的时刻"等同"浮标被观看的时刻"**——用户会在打字中、切页时、看历史时瞟它。教训:涉及用户注意力的假设,以用户实际行为为准,不以功能语义为准。
- **CDP 可用假设**:通用 Chromium 知识(Electron 支持远程调试开关)在"发行版 Electron+安全收紧的 Chromium 代际+厂商默认不配置"三重叠加下失效。这类"标准能力被宿主策略杀死"只能实测发现,文档不会写。

## 五、决策复盘(否决/换轨的模式归类)

本轮三次大换轨/多次方案反复,归为四类模式:

1. **单点正确 ≠ 集合正确**(常量锚、pid 锁、CDP 单开关、首目标初始化):每个方案在其假设成立时完美,环境一动即死。共性解法都是"降级链":UIA→降级锚→保持原位→基线;句柄锁→自愈接力→ZCode 亡自退。**没有降级路径的方案在这个宿主环境里都是脆的**。
2. **测量仪器先于被测物**(FindWindowW 灵异返回 0、元素计数通过但渲染隐形、Invoke 点击"成功≠生效"、node 读锚撞写入窗口):四起"被测物看起来坏了"最终都是仪器在说谎。模式:异常结论出现时,**先换一台仪器复测,再动被测物**。一次性查询 vs 常驻探针对照、EnumWindows 替代 FindWindowW、像素验证替代 DOM 计数,都是这条。
3. **状态语义细分驱动收敛**(三连"不动了"的归因链):同一表象(浮标不动)背后是三种 none、两种目标、两种偏移。每次 bug 修复的实质都是把一个混合语义拆成两个正交语义。**表象相同 ≠ 语义相同,合并处理就会互相打架**。
4. **测试覆盖的层级错位**(CDP 5 态全过但真机即死):测试验证了消费端,没验证生产端的存在性。**对引入外部依赖的方案,"依赖可达性"必须是第一个测试项**,排在一切功能测试之前。

## 六、方法论沉淀(可复用打法)

- **源码考古三件套**:官方开源仓库(类名/结构/token)> 本地 asar(哈希 chunk,只作佐证)> 截图目测(最后手段)。还原类需求先问"有没有源头"。
- **假锚注入测试法**:定位/跟随类逻辑,用假锚文件驱动全状态机(位置逐像素断言),不依赖真实 UI 就能回归。
- **三路同采归因法**:间歇故障(闪现/抖动)用 editor+锚+浮标矩形同频采样,一眼定位哪一层在摆。工具族留存:`~/.zcode/workspace/default/{jitter-sampler,anchor-flap-probe,dual-sampler,widget-verify,widget-scan,uia-probe-test,a11y-dump}.ps1`。
- **一次性 vs 常驻对照**:常驻进程行为异常时,起一次性查询做同条件对照,分离"进程劣化"与"环境变化"。
- **像素出数校准**:几何常量必须扫描实测(假设值曾差 281px);对齐验证用圆角弦高等几何公式闭合误差解释。
- **计算机实操验收**:computer-use 截图定位+event 点击+高频采样,让"用户报告的 bug"变成可复现的量化轨迹(backJumps/settleMs 指标)。
